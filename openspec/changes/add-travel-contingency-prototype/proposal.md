# Proposal

## Why

海外自由行旅客遇到交通異動、景點休館或店家無法前往時，需要判斷資訊可信程度並選擇下一步。先以可點擊 Prototype 驗證「可信度卡片＋情境式應變選項」能否幫助完成決策並避免錯誤採信，再決定是否投入真實資料整合。

## What Changes

- 提供主動回報與既有行程「需要調整」兩種入口，帶入位置、當地時間及原安排。
- 第一輪涵蓋交通、景點／店家異常；重要資訊呈現來源、更新時間、適用時段與「已確認／仍需確認／無法確認」。
- 依資訊類型與時間有效性判斷狀態，不能僅因來源為官方就視為已確認；處理事件公告與固定資料的差異。
- 以「最省時間／最少改動／其他推薦」固定策略呈現推薦地點或替代行程，讓使用者比較、選擇下一步。
- 依使用者本輪澄清：即使關鍵資訊無法確認，仍提供推薦地點或行程供選擇；保留未知事項與可信度提示，不沿用原文件 Page 8 Rule 3「僅能提供查證步驟」的暫定限制。
- 使用可重現的模擬情境驗證流程，明示資料及推薦內容為模擬；記錄決策完成、可信度理解、二次查證與耗時，供人工判讀。
- 本輪不包含完整行程生成、全旅程持續監測、主動預警、自動重排或真實即時資料／AI API 整合承諾。

## Capabilities

### New Capabilities

- `travel-contingency`: 異常回報、脈絡輸入、策略式推薦與下一步選擇。
- `travel-information-confidence`: 資訊證據、時間有效性、三段可信度與不確定資訊呈現。
- `contingency-validation`: 模擬情境與工作階段觀察記錄，支援核心價值與錯誤採信驗證。

### Modified Capabilities

無；目前沒有既有規格。

## Impact

- 依據根目錄《AI 旅遊行程生成後的查證與即時應變.md》與本輪使用者澄清規劃。
- 目前專案沒有應用程式、測試或套件設定；屬新建 Prototype，後續需建立互動介面、情境資料、狀態判定與觀察記錄。
- 本輪資料與推薦由可替換的模擬供應器提供，呈現未來「固定策略＋AI 動態內容」的互動契約；真實來源與模型整合留待後續驗證。
- 市場需求、成效、主要指標與量化門檻仍待研究，不宣稱已驗證或已上線。
