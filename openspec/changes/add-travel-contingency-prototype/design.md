# Design

## Context

動機與範圍見 proposal.md。根目錄目前只有需求 Markdown 與 OpenSpec，沒有既有應用、套件設定或可重用的行程服務。設計以第一輪可操作、可重現的研究 Prototype 為目標，介面採繁體中文並支援手機寬度。依來源文件 Roadmap，真實資料與模型整合屬 NEXT。

使用者已澄清：無法確認資訊時仍要有推薦地點或行程可選；此決策優先於來源文件 Page 8 Rule 3 的 AI 暫定限制。來源內較早的候選分類含「最近替代方案」，本輪採 Page 7 已確認的「最省時間／最少改動／其他推薦」，距離可作為其他推薦理由。

## Goals / Non-Goals

**Goals:**

- 將證據判定、推薦內容與畫面狀態分離，使「是否推薦」不會自動決定「是否已確認」。
- 使用固定情境時間重現時區、資料衝突與未知時間案例，降低展示與測試差異。
- 讓點選事件與研究者對決策品質的判讀分開，保留可檢視記錄。

**Non-Goals:**

- 本輪不建立帳號、後端儲存、行程匯入、定位權限、爬蟲或外部資料／AI API 整合；既有行程入口使用展示行程。
- 模擬供應器僅驗證動態內容呈現契約，不宣稱已評估模型生成品質或推薦最佳性。

## Decisions

### 1. 本地 Web Prototype 與可替換供應器

建議採 Vite、React、TypeScript 建立單頁介面，使用本地情境資料與記憶體狀態，避免第一輪引入後端及憑證依賴。這是新專案的實作預設，並非既有技術約束。

替代方案：純靜態點擊稿無法充分驗證狀態規則與記錄；完整線上服務會把來源串接與模型品質混入可用性驗證，增加成本。本輪以可替換資料供應器接收問題、位置、當地時間與原安排，回傳事實、證據與分策略候選；無匹配情境時提供明確未涵蓋提示及可用情境，不假裝完成通用搜尋。

### 2. 資料模型與時間語意

- 脈絡：問題、位置、目的地時區、含當地日期時間的查詢時刻、可空原安排、入口。
- 事實：識別、交通／景點／店家類型、敘述、證據清單。
- 證據：來源名稱／可空 URL、第一方標記、目前狀態／事件／固定資料類型、來源更新時間、系統取得時間、適用起迄與時區；缺值保留空值。
- 推薦：策略、地點或替代步驟、推薦理由、估計耗時、原安排影響、引用的事實識別與待確認條件。
- 任務記錄：匿名工作階段、情境與入口、時間、呈現狀態、候選及選擇、來源開啟、人工觀察與評估狀態。

查詢以目的地當地時刻為準，不依電腦所在地日期。事件區間採含起點、不含終點；固定情境時間可編輯但不能冒稱電腦目前時間即為當地時間。替代方案是只儲存時間文字，會使跨日期公告難以穩定判斷。

### 3. 可信度判定為獨立純規則

依 travel-information-confidence/spec.md 逐項輸出狀態、原因與採用證據。先檢查有效時段，再處理官方目前／事件資料優先於固定資料；無法解決的同級衝突、更新時間不明或不足以判讀時標為無法確認。已過期公告不證明目前異常；若仍有固定時刻表，僅能提供仍需確認資訊。

不額外編造「幾分鐘內有效」的更新頻率標準：情境的官方目前狀態須明示涵蓋查詢時刻。未來真實供應器須另定更新政策，本輪不以真實資料接入為前提。替代方案是讓模型自行給信心分數，無法穩定對應來源文件的三段規則，因此不採用。

### 4. 推薦與不確定性並存

採「入口 → 脈絡 → 現況卡片＋策略選項 → 選擇摘要」流程。手機以垂直卡片顯示；狀態包含文字與原因，來源可開啟，策略可鍵盤選擇。每個推薦引用相關事實，不做全面已確認徽章。

無法確認時保留候選推薦與查證入口；選擇摘要保留未知條件。沒有候選則顯示缺少內容的分類與補充方式，不用未知狀態作為整頁禁止推薦的理由。修改脈絡會清除舊結果及選擇，再更新結果。原行程保持展示資料，選擇只記錄應變決策。

### 5. 記錄支援研究判讀

以記憶體儲存工作階段任務，提供本地 JSON 匯出與明確重設；頁面重載前提示尚未匯出記錄會消失，不上傳自由文字或精確位置。新任務使用獨立識別，既有記錄保留至明確清除；重設當前情境未結束的任務記為放棄。

點選方案是事件；「是否完成可執行決策／是否錯誤採信」由研究者標記，可選未評估。來源開啟可記錄，但外部工具查證需人工補記，不能由無點擊推論沒有查證。

研究說明定義：完成率＝完成可執行決策任務／全部測試任務；錯誤採信率＝將不確定資訊誤認已確認的任務／呈現仍需確認或無法確認資訊的任務。以每次工作階段為期間，兩者採任務單位避免一次任務重複計數。保留未評估數，資料不完整不輸出單一確定率；分母零標不適用。主要指標仍屬暫定研究操作定義。

替代方案是外部分析平台；本輪不需追蹤正式營運，使用本地匯出足以供研究者檢視。

## Risks / Trade-offs

- [模擬推薦可能讓使用者誤以為完成真實查證] → 全流程明示模擬；即使情境內已確認，也不表示現實今日資訊已確認。
- [無法確認仍可選方案，可能增加錯誤採信] → 卡片與摘要保留逐項狀態、未知條件及來源，以觀察記錄評估理解。
- [固定三策略未經驗證] → 納入比較卡點與訪談，不宣稱一定符合所有旅客需求。
- [記憶體記錄會在重載後消失] → 提供本地匯出與重設說明，不承諾永久儲存。
- [自由文字超出展示情境無法產生真實方案] → 明示情境範圍及可用示例；真實模型品質屬後續工作。

## Migration Plan

無既有應用或資料需要遷移。後續 apply 階段建立本地執行與建置指令、情境資料與研究說明，完成規則測試及兩入口互動驗收後供本地測試。若需撤回，移除 Prototype 應用檔案即可；OpenSpec 規劃與原始需求文件保留。本輪不部署或發布網站。
